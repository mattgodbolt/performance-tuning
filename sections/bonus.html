Bonus: std::format

"Someone always asks: what about std::format?" Modern, type-safe, but not free.

What about std::format?

  • C++20, type-safe, no printf format-string footguns
  • What you'd write today instead of stringstream

/// hide
#include <format>
#include <string>
#include <string_view>
/// unhide
std::string newOrder(std::string_view stock,
                     int price, int quantity) {
  return std::format("NEW {} {} {}",
                     stock, price, quantity);
}

std::format_to - in-place

If you already own the buffer (à la Take Two):


/// hide
#include <format>
/// unhide
void newOrder(char *buf, const char *stock,
              int price, int quantity) {
  std::format_to(buf, "NEW {} {} {}",
                 stock, price, quantity);
}

Is it free?

Version ns / order
stringstream ~310
sprintf ~115
std::format ~118
std::format_to ~117
custom Format ~18
"best" ~7
  • Type-safe replacement for sprintf... and roughly the same speed
  • Sink/iterator generic plumbing eats most of the win from clever itoa
  • Asm: sprintf → ~9 lines · std::format → ~25k lines
  • For the last 10×, the custom Format still wins
Surprised me too - I thought format_to would be near custom-Format speed because libstdc++ uses similar two-digit tricks. The integer formatting kernel is fast; the iterator/ sink machinery wrapped around it isn't. The 25k asm lines are everything inlined in CE - most of it is cold paths for non-integer types - but it's a useful signal of how much template machinery is in flight.
